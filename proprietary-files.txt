#
# clover firmware blobs: everything the firmware volume needs that is not in
# this repository.
#
# Why this file exists
# --------------------
# Mu-Silicium gets its prebuilt Qualcomm DXE drivers from the
# Project-Silicium/Device-Binaries submodule, laid out as Binaries/<device>/.
# That submodule ships 75 device directories and clover is not one of them:
# the closest entry is lavender (Redmi Note 7, also SDM660) and the tablet's own
# firmware has never been dumped into it.  Verified against the tree of
# Project-Silicium/Device-Binaries@main, whose top level is:
#
#   9707f a52q a52sxq alioth aston b4q b5q bale_b beryllium bitra caprip
#   caymanslm cebu cepheus cheeseburger citrus dm2q dodge enchilada equuleus
#   fog garnet generic ginkgo giulia gta4l gta9pwifi gts8p gts9wifi i005d
#   infiniti ingres j706f kebab laurel_sprout lavender lemonade lime lisa
#   macan marble mh2 miatoll muyu nabu nitrogen nuwa nx729j onyx pagani
#   peridot phoenix pipa polaris pong q2q qrd8550 r0q r8q r9qb2 renoir salami
#   senna_a senna_bc spacewar spes starqltechn surya sweet_k6a tapas vayu
#   venus veux vili willow
#
# So `Binaries/clover` has to be produced locally, from the tablet's own stock
# firmware, before clover.dsc can build.  Nothing in this overlay is a stub or a
# placeholder: every module listed below is a real DXE driver that upstream
# extracts for lavender, with the same directory and file names.
#
# It has been produced, and the way it was produced is the way to do it again:
# scripts/extract-clover-blobs.py reads the firmware volume out of the unit's own
# xbl image and writes each module this repository asks for, plus a regenerated
# stub INF.  See "How to extract" below.
#
# Line format
# -----------
#   <marker> <path>
#
#   path     relative to the root of a Mu-Silicium checkout (that is also where
#            the `Binaries/` submodule is mounted).
#   R        required: clover.dsc/clover.fdf will not build without it
#   O        optional: the module is in the volume but sits behind a clover.dsc
#            guard that this board has off (USE_CUSTOM_DISPLAY_DRIVER), so no
#            build fails without it; flip the guard and it becomes R
#
# Everything after a "#" is a comment, blank lines are ignored.  There is no
# third marker: clover.dsc asks for nothing under Binaries/generic, which is
# why the XHCI stack upstream shares has its own note at the foot of this file.
# scripts/check-clover-uefi.py reads this manifest, cross-checks it against the
# INF paths in Platforms/Xiaomi/cloverPkg/Include/{APRIORI,DXE}.inc, and reports
# exactly which files are still missing from a checkout.
#
# How to extract
# --------------
# 1. clover has no `uefi` partition.  The GPT (facts/<serial>-<stamp>/
#    partition-names.txt, mmc_partitions.txt) has xbl, xbl_cfg, tz, hyp, sec,
#    abl, ... and nothing named uefi: the SEC in xbl gunzips a firmware volume
#    that lives *inside the same partition*.  Dump that partition:
#
#       fastboot fetch xbl xbl.img          # or dd if=/dev/block/mmcblk0p1
#
#    scripts/dump-clover-blobs.sh in UniXNU-clover does exactly this and keeps
#    the gzip stream and its uefiplat.cfg under facts/<serial>-<stamp>/fw/.
#
# 2. Hand it to the extractor.  It finds the gzip stream, inflates it, checks the
#    volume header (`_FVH`, FFS2 FileSystemGuid, FvLength 0x459040 on this unit),
#    walks the 83 FFS records, and writes only what the three include files ask
#    for -- so the blob set on disk is exactly the build's request list:
#
#       python3 scripts/extract-clover-blobs.py --xbl xbl.img
#       python3 scripts/extract-clover-blobs.py --xbl xbl.img --list   # inventory
#
#    Add `--list` first to see the volume without writing anything, and
#    `--out <dir>` to build somewhere else.  Binaries/ is gitignored: the blob
#    set comes from a device nobody else owns, its provenance is the dump, and
#    this manifest is the reviewable contract.
#
# 3. The extractor regenerates the stub INF for each export, in the shape
#    Device-Binaries uses (upstream's clean_up.py post-processes these):
#
#       [Defines]
#         INF_VERSION  = 0x0001001B
#         BASE_NAME    = EnvDxe
#         FILE_GUID    = 90A49AFD-422F-08AE-9611-E788D3804845
#         MODULE_TYPE  = DXE_DRIVER
#         VERSION_STRING = 1.0
#         ENTRY_POINT  = EfiEntry
#       [Binaries.AARCH64]
#         DXE_DEPEX|EnvDxe.depex|*
#         PE32|EnvDxe.efi|*
#       [Depex]
#         TRUE
#
#    FILE_GUID always comes from the firmware volume entry itself, never from
#    lavender: the GUID identifies the module inside the FV, and the module names
#    in the vendor's own build path disagree with upstream's directory names in
#    several cases.  The GUID is the join key, and every module this board
#    carries matched a GUID upstream already publishes.
#
# 4. Run scripts/check-clover-uefi.py --checkout <checkout> until it reports no
#    missing files, then build (see README.md).
#
# Ordering note: a module without a .depex line in the list below genuinely has
# no depex upstream either (HashDxe, LimitsDxe and RngDxe are UEFI_DRIVER
# modules whose stub declares only PE32), so do not fabricate one.
#

# ---------------------------------------------------------------------------
# Raw configuration blobs (Binaries/clover/RawFiles)
# ---------------------------------------------------------------------------

# Firmware-volume payloads carried by Include/RAW.inc.  Without SecParti.cfg
# the Qualcomm partition drivers cannot map slot names to LUNs, which is the
# difference between "the ESP shows up" and "nothing to boot from".
#
# The four FREEFORM GUIDs in RAW.inc are the device's own: the tablet's firmware
# volume names SecParti.cfg A1E235DE-..., tracer_event.cfg F12A1F3D-...,
# QcomChargerCfg.cfg 45FE4B7C-... and BATTERY.PROVISION F780C779-... (run
# scripts/extract-clover-blobs.py --xbl <dump> --list and look at the
# USER_INTERFACE,RAW records).  Upstream uses the same GUIDs for the same blobs,
# so the prebuilt drivers find them either way.
R Binaries/clover/RawFiles/SecParti.cfg
R Binaries/clover/RawFiles/QcomChargerCfg.cfg
R Binaries/clover/RawFiles/BATTERY.PROVISION
R Binaries/clover/RawFiles/tracer_event.cfg

# Two blobs the lavender manifest carries are NOT in this volume, so nobody
# should add them back from a template: `battery_miui.bmp` (Xiaomi's own boot

# is not an FV record at all -- it is a file inside the xbl partition, ahead of
# the gzip stream.  Its contents matter more to this port than any driver does:
# [MemoryMap], [RegisterMap] and [ConfigParameters] are transcribed verbatim into
# Library/MemoryMapLib and Library/ConfigurationMapLib, and the copy extracted
# from the tablet lives at UniXNU-clover/facts/<serial>-<stamp>/fw/xbl-uefiplat.txt.

# --- clocks, power, remote processors ---------------------------------------
#
# ClockDxe is the clock producer SdccDxe waits on.  The stock blob spins
# forever in two hardware handshakes (an RCGR update and a GDSC power-on
# ack), and dispatch stops there before any display driver or BDS runs.  The
# INF therefore links ClockDxe.patched.efi, the same six-call edit upstream
# ships under that name: scripts/clockdxe_patch.py turns the six BL

# --- display -----------------------------------------------------------------
# Nothing in the volume touches the display: ABL brings MDSS, the nt51021 panel
# and the pm660l backlight up and leaves them scanning the 1200x1920 window at
# 0x9D400000 ("Display Reserved" in this unit's uefiplat.cfg; clover-overlay.dtsi's
# 0x9D500000 is the Android kernel's own reservation and the firmware beats it).
# CloverGopDxe publishes the GraphicsOutput over that window and is the only
# code that writes to it.
#
# The vendor DisplayDxe blob is not linked.  It was, under the
# USE_CUSTOM_DISPLAY_DRIVER branch lavender uses, and the bring-up measured the
# conflict: bands this firmware painted appeared and then vanished, with the
# backlight left on -- the blob had taken MDSS over.  Extracting it is still
# harmless (it documents where the blob comes from), so the three lines are O
# rather than R: a build that does not read them is a build that has not silently
# grown a second panel owner.
O Binaries/clover/QcomPkg/Drivers/DisplayDxe/DisplayDxe.inf
O Binaries/clover/QcomPkg/Drivers/DisplayDxe/DisplayDxe.efi
O Binaries/clover/QcomPkg/Drivers/DisplayDxe/DisplayDxe.depex
